# Envelope

Every OLF record is a single JSON object. The **envelope** is the set of common
fields carried by records of every type. The type-specific data lives under
`payload`.

```jsonc
{
  "id":          "0192f3a0-7b1e-7c3d-8e4f-0a1b2c3d4e5f",
  "type":        "sleep",
  "olf_version": "1.0",
  "occurred_at": "2026-05-28T23:00:00+09:00",
  "recorded_at": "2026-05-29T07:10:00+09:00",
  "tz":          "Asia/Tokyo",
  "source":      "mobile-app",
  "payload":     { /* type-specific */ }
}
```

## Fields

| Field | JSON type | Req. | Description |
|---|---|---|---|
| `id` | string | MUST | Record identity. A [RFC 9562](https://www.rfc-editor.org/rfc/rfc9562) UUID. |
| `type` | string | MUST | Record kind. A standard short name, or a reverse-DNS extension name. |
| `olf_version` | string | MUST | Version (`major.minor`, semver-style, no patch) of the payload schema for `type`. |
| `occurred_at` | string | MUST | When the event occurred. Offset-bearing ISO 8601 date-time. |
| `recorded_at` | string | MUST | When the record was created/ingested. Offset-bearing ISO 8601 date-time. |
| `tz` | string | OPTIONAL | IANA Time Zone Database name for the place of occurrence. |
| `source` | string | MUST | Identifier of the client that recorded the record. |
| `payload` | object | MUST | Type-specific data. Validated by the type's JSON Schema. |

No envelope fields beyond these are defined in OLF 1.0. A reader MUST tolerate
unknown envelope fields (forward compatibility); see
[Type system § Envelope evolution](./type-system.md#envelope-evolution).

### `id`

- MUST be a valid UUID per RFC 9562, serialized in the canonical lowercase
  hyphenated form.
- **UUIDv7 is RECOMMENDED** because it is time-ordered, which improves storage
  locality and makes range scans cheap. Other UUID versions are accepted.
- Generated by the producer (client-side). It is the unit of **idempotency and
  deduplication**: a store MUST treat `id` as unique (see
  [On-disk § Mutation](./on-disk.md#mutation-and-uniqueness)).

### `type`

- A **standard** type is a short lowercase name matching `^[a-z][a-z0-9_]*$`
  (e.g. `meal`, `sleep`). Standard names are reserved by this specification.
- An **extension** type uses a reverse-DNS namespace; see
  [Type system § Namespacing](./type-system.md#namespacing).
- `type` selects which payload schema validates `payload`.

### `olf_version`

- A two-component version string `major.minor` (e.g. `"1.0"`, `"1.3"`) —
  semver-style semantics (see [Type system § Versioning](./type-system.md#versioning)),
  but with no patch component.
- It is the version of the **payload schema for `type`**, not a version of the
  envelope or of the format as a whole.
- A record retains the `olf_version` it was written with, forever. See
  [Type system § Versioning](./type-system.md#versioning).

### `occurred_at` and `recorded_at`

- Both MUST be **offset-bearing** ISO 8601 / RFC 3339 date-times, e.g.
  `2026-05-28T23:00:00+09:00`. A bare local time without offset, or a
  `Z`-normalized time that discards the local offset, is **NOT** conformant for
  natively recorded data (`Z` is permitted only when the event genuinely
  occurred in UTC).
- Because the offset form encodes the **local wall-clock time**, the local
  calendar date is simply the date portion of `occurred_at`. This is the
  partition key used by [On-disk layout](./on-disk.md) — no time-zone
  computation is required to bucket a record by day.
- `occurred_at` is the **primary timestamp** of the event:
  - For **point** events (e.g. `weight`, `meal`), it is the instant of the
    event.
  - For **interval** events (e.g. `steps`, `sleep`), it **MUST equal the start
    of the interval**. The end of the interval is carried in the payload
    (`ended_at`); the start is therefore not duplicated in the payload.
- `recorded_at` MAY differ from `occurred_at` (e.g. an event entered the next
  morning, or a backfilled import). It SHOULD be `>= occurred_at` but this is
  not required (clock skew, corrections).

### `tz`

- OPTIONAL, but producers **SHOULD** include it for natively recorded data.
- A value from the [IANA Time Zone Database](https://www.iana.org/time-zones)
  (e.g. `Asia/Tokyo`, `America/New_York`).
- Its purpose is **zone identity** — recording *which zone the user was in* and
  enabling DST-correct reasoning later. It is **not** needed to compute the
  partition date (the offset in `occurred_at` already fixes the wall-clock
  date). Two zones can share an offset (`Asia/Tokyo` vs `Asia/Seoul`); `tz`
  preserves the distinction that the offset alone loses.

### `source`

- A short client identifier slug matching
  `^[a-z0-9]([a-z0-9-]*[a-z0-9])?$` (e.g. `mobile-app`, `import-script`,
  `web-client`).
- It answers "who wrote this record" in one token. Richer provenance (client
  version, request id, user agent) is intentionally **not** modeled here; it
  belongs to a runtime's audit log, not to the portable record.

## Full example

```json
{
  "id": "0192f3a0-7b1e-7c3d-8e4f-0a1b2c3d4e5f",
  "type": "weight",
  "olf_version": "1.0",
  "occurred_at": "2026-05-28T07:05:00+09:00",
  "recorded_at": "2026-05-28T07:06:12+09:00",
  "tz": "Asia/Tokyo",
  "source": "mobile-app",
  "payload": {
    "weight_kg": 70.5,
    "body_fat_percent": 18.2
  }
}
```
